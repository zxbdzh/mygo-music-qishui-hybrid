# 协作流程

本文件只补充开工卡、实现、验证和交接。根目录及更深层项目规则优先。

## 六步流程

1. **定边界**：写清目标、非目标、验收条件、影响范围、风险和负责人。
2. **读证据**：检查工作区、相关源码、测试、规范和已有决定，保留用户改动。
3. **说方案**：行为改动先准备匹配版本的开工卡。纯展示或文档改动只说明位置、依据和验收。
4. **小步实现**：只实现已批准范围，复用现有入口和约束。
5. **验证复核**：先跑目标检查。高风险变更补专项验证和独立复核。
6. **交接留痕**：报告实际路径、命令、结果、回滚方式、风险和未验证项。

## 开工卡

普通业务开工卡必须包含：

- 本次交付与明确后置内容
- 业务规则、操作者、影响对象和失败处理
- 含成功与失败分支的流程图
- 受影响模块，以及复用或新增的 service/API。API 写方法、路径、输入和结果；没有新增时明确写复用
- 少量成功、拒绝和失败后保留数据的 BDD 场景
- 关键失败测试草稿、复用测试入口、集成前提和未覆盖范围
- 方案版本、负责人、批准边界，以及计划、模拟、真实测试和验收状态

BDD 使用 Given–When–Then，描述可观察结果；失败场景说明输入或原数据如何保留。负责人对明确版本和范围的回复才算批准，旧 Note、标签、任务分配或 Agent 自审不能替代。

权限、账本、任务状态与重试、迁移、上传、供应商调用和部署还要补数据保护、回滚、专项验证和独立复核。

本项目的“供应商调用”包括汽水官方接口、第三方解析服务（音源）和音频 CDN；播放链路改动按高风险处理。

## 授权

- 只读调查、已批准范围内的局部补丁和隔离测试可自主执行。
- 新依赖、架构变化、技能或 Hook 安装、全局配置、服务启停、迁移写库、提交推送和外部调用按项目授权规则单独处理。
- 删除、移动、整文件覆盖、跨目录批改和其他不可逆操作先说明影响与回滚。
