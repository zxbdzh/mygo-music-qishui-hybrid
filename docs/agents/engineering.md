# 工程规范

本文件提供跨项目的最小协作约束。技术栈、目录职责、性能目标和产品规则以项目现有文档为准。

## 实现

- 先复用已有模块、组件、service、API、测试夹具和命令。
- 不为简单逻辑新增空壳层、通用包装或预留配置。
- 复杂业务逻辑、关键配置、非直观校验、状态转换和边界处理附近使用简洁中文注释，说明原因和约束。
- 权限与信任边界由服务端或实际数据源判断。客户端显隐不能替代鉴权。
- 不把凭据、会话、完整敏感内容或原始供应商错误写入代码、日志、文档和测试。
- 改变用户可观察行为时，先确认匹配版本的开工卡和关键失败测试草稿。

## 本项目的结构约束

- `src/plugin.mjs` 是插件源码入口，`index.js` 是 esbuild 产物；改源码后必须 `npm run build`，提交前用 `npm run check` 校验产物一致。
- 宿主加载的是 `index.js`，不是 `src/`；不要在 `index.js` 里手改逻辑。
- `helper/*.mjs` 中 `worker/playback/audio-server/native` 是 Node 验证适配器，只进 validation 包；生产运行时走 `native/worker` 的 Go 二进制。
- 插件只在宿主沙箱里运行：网络受 `plugin.json` 的 `permissions.network` 限制，子进程受 `permissions.process` 限制；新增外部域名或可执行文件必须同步改权限声明。
- 登录态、API Key 等凭据只留在 JS 侧 `host.storage`，不得传给 Go worker，也不得写进日志。

## 高风险

权限、账本、任务状态与重试、迁移、上传、供应商调用和部署改动必须说明：

- 数据保护和幂等边界
- 失败后的保留、恢复或回滚路径
- 与改动对应的专项验证
- 独立复核范围和证据

没有批准范围时只做只读调查和开工卡，不写业务实现、模型迁移或真实外部调用。
