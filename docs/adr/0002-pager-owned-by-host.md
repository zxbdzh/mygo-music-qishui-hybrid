# 翻页由宿主实现，插件只声明批次与下一页

听歌模式和首页的探索卡改成按**一屏一页**左右翻页。翻页容器、吸附、按钮、键盘和页码属于宿主（`F:\github\mygo-music`）；插件只在 section 上声明"还有下一批、下一批的页 id"，宿主翻到最后一屏时才按需取批。

## Context

插件只能给宿主返回 `{title, subtitle, sections}` 页面数据，宿主把它们按窗口列数排成自动换行的网格行，没有任何横向滑动或翻页能力；插件自身拿不到画布，也没有自定义组件通道。另一条路是不改宿主、在插件里做"上一批 / 下一批"跳页，但那是跳页而不是翻页。宿主所用的 UI 框架本身有横向滚动与吸附对齐，能力缺口在宿主渲染层，不在框架。

## Considered Options

- **插件侧分批跳页**：零宿主依赖，今天就能发；但观感是"点一下换一批"，且每个新页面都要靠宿主原生前进后退才回得去。
- **插件一次返回多批、宿主本地翻**：翻页零等待，但首屏请求和流量放大数倍，探索的去重与曝光状态要一次算清。
- **宿主持有翻页、插件按需给下一批**：手感是真正的翻页，数据仍是增量取，和现有 cursor 状态机一脉相承；代价是要改宿主并抬插件的 `minAppVersion`。

## Consequences

- 新字段必须对旧宿主**可忽略**：旧宿主不认就退回没有翻页的普通网格行，不报错。
- 第 1 页放**常用模式**一行，之后只放探索卡：8 个模式和"一屏一页"在同一屏里装不下，多出来的模式由"查看全部"承接。
- 首页翻已有的那批卡（不新增取数），末尾留一张"更多"卡跳听歌模式：首页不做无限翻，避免和听歌模式职责重叠。
- 抬 `minAppVersion` 后删掉末尾的"换一批"链接卡：两套翻批方式并存会让"批次由谁推进"长期暧昧。
- 取数中该屏显骨架、箭头禁用；取数失败给可重试提示不跳页；批次状态过期或超出上限时静默从第 1 批重建。
